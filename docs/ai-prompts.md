## 模板一：測試驅動開發 - 單元測試編寫

### 情境

當你需要開發一個新功能時，首先請 AI 編寫單元測試（綠燈驅動開發法）。

### 指令模板

```
請根據以下需求撰寫單元測試：

【功能名稱】
{function_name}

【功能描述】
{description}

【輸入參數】
{input_parameters}

【預期輸出】
{expected_output}

【邊界條件與特殊情況】
- {edge_case_1}
- {edge_case_2}
- {edge_case_3}

測試框架：{jest/vitest/其他}
測試位置：{test_file_path}

請確保：
1. 測試覆蓋所有邊界條件
2. 每個測試用例有清晰的描述文字
3. 測試應該在實現功能前失敗（紅燈）
4. 使用 TypeScript，嚴格定義所有輸入輸出型別
```

### 實例

```
請根據以下需求撰寫單元測試：

【功能名稱】
calculateNodeValue

【功能描述】
根據輸入的節點配置和狀態，計算節點的最終數值。若無輸入值，預設為 0。

【輸入參數】
- nodeId: string
- inputs: Record<string, number>
- operations: Operation[]

【預期輸出】
- result: number

【邊界條件與特殊情況】
- 空輸入應返回 0
- 負數輸入應正確處理
- 除以零應返回 Infinity 或拋出錯誤

測試框架：vitest
測試位置：src/__tests__/calculateNodeValue.test.ts

請確保：
1. 測試覆蓋所有邊界條件
2. 每個測試用例有清晰的描述文字
3. 測試應該在實現功能前失敗（紅燈）
4. 使用 TypeScript，嚴格定義所有輸入輸出型別
```

## 模板二：實現功能邏輯

### 情境

單元測試已編寫並驗證失敗後，請 AI 實現功能邏輯，使測試通過。

### 指令模板

```
測試已編寫完成並處於失敗狀態。請實現以下功能邏輯：

【功能檔案位置】
{implementation_file_path}

【功能簽名】
{function_signature}

【實現要求】
{requirements}

【相關依賴】
- {dependency_1}
- {dependency_2}

【特別注意】
- {constraint_1}
- {constraint_2}

實現後測試應該通過（綠燈）。
```

### 實例

```
測試已編寫完成並處於失敗狀態。請實現以下功能邏輯：

【功能檔案位置】
src/utils/calculateNodeValue.ts

【功能簽名】
export function calculateNodeValue(
  nodeId: string,
  inputs: Record<string, number>,
  operations: Operation[]
): number

【實現要求】
1. 接收節點ID和輸入值
2. 按照操作列表依序執行計算
3. 若無任何輸入，返回 0
4. 支援加、減、乘、除四種基本運算

【相關依賴】
- types.ts（Operation 型別定義）

【特別注意】
- 業務鐵律：不允許任何預設非零數值
- 必須使用 TypeScript，型別嚴格定義
- 不應該有任何 any 型別
```

## 使用指南

### 💡 最佳實踐

1. **始終從測試開始**：先寫測試（紅燈），再實現功能（綠燈）
2. **明確提供上下文**：包含檔案路徑、型別定義、邊界條件
3. **逐步迭代**：若測試失敗，複製錯誤訊息給 AI，讓它逐次修復
4. **驗證輸出**：接收 AI 的代碼後，必須在本地運行測試驗證
5. **版本追蹤**：每次重要修改後立即提交，方便追溯

### ⚠️ 禁止事項

- ❌ 不要跳過單元測試直接實現功能
- ❌ 不要使用 `any` 型別或禁用 TypeScript 檢查
- ❌ 不要設置預設非零數值（核心業務鐵律）
- ❌ 不要在 `main` 分支直接開發，必須建立 feature branch

### 🔄 標準開發流程

```
1. 從 main 分支拉取最新代碼
2. 建立 feature branch: git checkout -b feature/your-feature
3. 使用「測試編寫」模板讓 AI 寫測試
4. 執行測試，驗證失敗（紅燈）
5. 使用「實現功能」模板讓 AI 寫實現
6. 執行測試，驗證通過（綠燈）
7. Commit 和 Push（Husky 會自動檢查）
8. 發起 Pull Request 並指定審查者
9. 完成代碼審查後合併到 main
```
