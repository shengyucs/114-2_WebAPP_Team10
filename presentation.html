問題背景

RPG 數值公式極為複雜：
攻擊力 = (基礎 + 裝備) × (1 + 強化%) × 條件 buff

傳統工具的痛點：

  • Excel 無法呈現計算資料流向
  • 程式碼公式不透明、難調整
  • 缺乏可互動的計算建模工具

解決方案目標

像 Unreal Engine Blueprint 一樣

  • 支援條件分支與流程控制
  • 全域變數系統（模擬狀態機）
  • 無需帳號，一鍵 URL 分享

核心算法

Kahn's Algorithm — 拓撲排序

後端計算引擎使用 Kahn 演算法對節點圖進行拓撲排序，同時偵測循環依賴。 

// 1. 計算每個節點的入度
for (const edge of edges) {
  inDegree.set(edge.target,
    (inDegree.get(edge.target) ?? 0) + 1);
}

// 2. 從入度=0的節點開始排序
while (queue.length > 0) {
  const current = queue.shift()!;
  sorted.push(current);
  // 展開鄰居節點...
}

// 3. 長度不符 → 有環！
if (sorted.length !== nodes.length) {
  throw new CircularDependencyError();
}

執行流程

1
建立入度表
計算每個節點被多少條邊指向
2
Queue 初始化
將所有入度 = 0 的節點加入佇列
3
逐節點計算
按拓撲序計算每個節點的輸出值
4
循環偵測
排序長度 ≠ 節點總數 → 拋出錯誤，前端封鎖連線
核心算法

NaN 傳播 — IfElse 流程控制

IfElse 節點輸出機制

條件 成立：true 輸出 = 1，false 輸出 = NaN

條件 不成立：true 輸出 = NaN，false 輸出 = 1

// NaN 向下游自然傳播 (JS 行為)
NaN + 10  = NaN   // Operator 傳播
NaN * 5   = NaN

// Output 節點：NaN 視為 0
results[id] = incoming.reduce((sum, edge) => {
  const v = resolveSource(edge, results);
  return sum + (isNaN(v) ? 0 : v);
}, 0);

// Set 節點：trigger 是 NaN → 不寫入
if (isNaN(triggerVal)) { results[id] = 0; continue; }

傳播鏈示意

IfElse：exp(50) > 100 → false
true 路徑輸出 = NaN（封鎖）
↓ NaN 傳播
Get(level)：trigger = NaN → 輸出 NaN
↓ NaN 傳播
Operator(+)：NaN + 1 = NaN
↓ NaN 傳播
Set(level)：trigger = NaN → 不寫入，level 維持不變
false 路徑：exp+10 正常執行 ✓
